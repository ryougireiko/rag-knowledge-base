# RAG 技术学习笔记

## 什么是 RAG

RAG（Retrieval-Augmented Generation）是一种结合检索和生成的 AI 技术架构。它的核心思想是在大语言模型生成回答之前，先从外部知识库中检索相关信息，然后将检索到的信息作为上下文提供给模型。这种方法让模型能够基于最新、最准确的信息来回答问题，而不是完全依赖训练时的知识。

## 为什么需要 Chunk 切片

在 RAG 系统中，Chunk 切片是数据预处理的关键步骤。完整的文档通常很长，如果以整篇文档作为检索单元，会带来多个问题：检索精度下降、无关信息过多、Token 消耗过大。通过将文档切分成适当大小的片段，我们可以实现更精准的语义匹配。

合理的 Chunk 大小通常在 256 到 1024 个字符之间。太小的 Chunk 可能缺少完整上下文，太大的 Chunk 又会降低检索精度。Chunk 之间适当的重叠可以确保语义的连续性，避免关键信息在边界处被切断。

## FastAPI 框架介绍

FastAPI 是一个现代、快速的 Python Web 框架，专门用于构建 API 服务。它基于 Starlette 和 Pydantic，提供了自动的 API 文档生成、请求验证、序列化等功能。在 RAG 项目中，FastAPI 常被用来构建知识库查询接口。

使用 FastAPI 可以快速搭建 RESTful API，支持异步处理，性能优秀。通过 Pydantic 模型定义，可以轻松实现请求和响应的数据验证，减少手动编写验证代码的工作量。

## Metadata 的重要性

Metadata（元数据）在 RAG 系统中扮演着关键角色。每个 Chunk 都需要保留其来源信息，包括原始文件名、在文档中的位置、切片的起止字符位置等。这些信息在后续的检索和引用阶段至关重要。

当系统检索到相关 Chunk 并生成回答后，可以通过 Metadata 追溯到原始文档的具体位置，实现答案的可溯源。这对于构建可信的 AI 应用非常重要，用户可以验证生成内容的依据。

## Embedding 的接入规划

虽然目前还没有接入 Embedding 模型，但已经在数据层面做好了准备。Embedding 是将文本转换为向量的技术，相似的文本会有相似的向量表示。通过将 Chunk 转换为 Embedding 向量，可以实现基于语义的相似度检索。

未来接入 Embedding 后，需要为每个 Chunk 生成向量表示，并存储在向量数据库中。查询时，将用户问题也转换为向量，通过向量相似度计算找到最相关的 Chunk，然后交给大模型生成最终回答。
